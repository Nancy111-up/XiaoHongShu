# V0.1 实施状态与运行计划

> 最后更新：2026-09-09
> 运行指南：[`README.md`](../README.md)

本文记录当前仓库实际实现的 V0.1 边界和下一步，不把旧版 Agent/看板设计当作已运行功能。

## 已实现的数据链路

```text
品牌资料 → 单一刷新任务 → MediaCrawler 搜索采集 → 标准化/聚类
        → 代表笔记详情与一级评论 → 机会评分（可选 LLM）
        → 机会工作台 → 草稿 → 排期 → 基础复盘
```

| 环节 | 当前实现 | 运行条件 |
|---|---|---|
| 品牌资料 | 版本化资料读写；关键词由定位、受众、场景与产品字段派生 | 先在“品牌大脑”保存至少一版资料 |
| 刷新任务 | FastAPI 进程内后台任务；数据库保证一次只有一个活动任务 | SQLite 与后端服务可用 |
| 数据采集 | 两阶段：每个关键词搜索，随后只抓取代表笔记详情和一级评论 | 固定的 MediaCrawler、正常人工登录 |
| 机会 | 保留笔记/主题/LLM 溯源，提供来源链接、评分、风险和置信度 | 成功采集；LLM 分析还需要 API key |
| 内容工作区 | 前端可展示草稿、日历、复盘和品牌资料的加载、空、错误与已填充状态 | 已有相应持久化记录 |
| 排期 | 保存 UTC 时间点，在前端按设备时区显示 | 已装配内容服务；不会自动发布 |

## 外部依赖和数据安全

- 仅接受 `config/mediacrawler.yaml` 指定的官方 MediaCrawler 副本与提交 `d6f7c5bb906b6dac40ddf343ef9e26438a3de092`。刷新前会验证远程地址、`HEAD` 和干净工作区。
- 登录始终是用户在可见浏览器中的二维码流程；不会绕过二维码、CAPTCHA 或平台限制。
- `DASHSCOPE_API_KEY` 是首选配置，`LLM_API_KEY` 是兼容别名；`LLM_BASE_URL` 与 `LLM_MODEL` 可覆盖默认 DashScope 兼容地址和 `qwen-plus` 模型。
- `data/`（包括 `data/raw/`、Cookie 和本地 SQLite 运行数据）、`external/MediaCrawler/` 与 `.env` 均被 Git 忽略。不得提交或输出 Cookie、令牌、原始抓取日志或密钥。
- 不使用假数据补充空状态。没有持久化机会时，API 返回不可用数据源，前端显示引导而不是演示记录。

## 操作和恢复规则

刷新从品牌资料派生关键词，前端轮询任务状态。任务会公开安全的阶段、成功/失败关键词和截断后的安全错误摘要，但不会公开 crawler stderr、Cookie 或令牌。

| 结果 | 含义 | 操作者动作 |
|---|---|---|
| `completed` | 搜索、详情和机会分析完成 | 复核机会与来源 |
| `partial_success` | 部分搜索/详情失败，或 AI 分析未配置/失败；已采集数据被保留 | 查看失败关键词/摘要，修复后重新刷新 |
| `failed` | 所有搜索关键词均失败，或刷新无法启动 | 检查固定副本、正常登录、品牌关键词和服务配置 |
| `REFRESH_ALREADY_RUNNING` | 另一任务仍活跃 | 不创建第二个任务；继续观察现有任务 |

完成的工作流应为：保存品牌资料 → 刷新热点 → 审阅机会及证据 → 接受机会并生成草稿 → 保存排期 → 在日历确认 → 在基础复盘查看累计数。每一步都必须由用户判断内容与品牌适配性；系统没有自动发布功能。

## 已知限制与下一步

1. 默认 `create_app()` 还没有在应用层装配 `ContentService` 的真实生成器和仓储。因此，当前默认本地启动能够完成品牌资料、刷新、已持久化机会与只读模块，但“接受/拒绝机会”和“草稿排期”会得到服务不可用响应。应先完成该装配及其端到端测试，再把它视为可操作的草稿链路。
2. LLM 缺失或不可用时，采集结果会保留，刷新标为部分完成；不会产生机会或草稿替代品。
3. 刷新使用 SQLite 与进程内背景任务，设计目标是单操作者、单活动任务；未提供队列、重试编排或高并发支持。
4. 基础复盘只有机会数、草稿数和草稿转化比；不代表发布、互动、投放或商业归因。
5. 浏览器登录、MediaCrawler、平台响应和第三方模型均是外部实时依赖。本次自动化验证不替代控制者本机进行的浏览器和提供方验收。
6. 完整严格 `mypy .` 目前会失败：独立 P0 probe 被重复发现，且严格模式还报告 probe 与测试辅助代码的既有注解问题。`mypy src` 可验证 57 个生产源文件；在将完整 mypy 设为发布门槛前，应单独修复/配置测试与脚本范围。
